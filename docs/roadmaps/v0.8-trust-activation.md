## PR 01 — Data-plane-only MCP and safe tool defaults

**Goal:** Remove storage administration from normal MCP clients and make a
safe read-only tool set the default.

**Key contracts (see ADR 0001):**
- Add `McpToolCategory` and `McpToolRisk` metadata to `ToolDefinition`.
- Remove `list_storages`, `add_storage`, `edit_storage`, `remove_storage`,
  `import_config`, `export_config`, `validate_storage` from public MCP
  discovery and dispatch.
- Desktop commands may continue to call the underlying Rust functions.
- Default enabled tools: `list_dir`, `stat_path`, `read_file`,
  `search_paths`, `list_versions`, `read_file_version`.
- Disabled by default: `mkdir`, `write_file`, `copy_path`, `move_path`,
  `delete_path`, `delete_version`, `generate_download_link`,
  `session_create`, `session_end`.
- Migrate legacy settings with a backup; intersect with the safe default.
- Replace "Enable all" with "Apply safe read-only" and
  "Configure advanced tools".

## PR 02 — Policy v2 and correct workspace grants

**Goal:** Create explicit, composable path grants and repair the current
Agent Workspace access semantics.

**Key contracts (see ADR 0002):**
- `McpStoragePolicy` version 2 with `rules`, `denied_paths`,
  `default_access`, `confirmation_rules`.
- `McpPathRule` with `id`, `prefix`, `access`, `source`, optional
  `confirmation_rules`.
- Evaluation order: mcp_exposed check → normalize → denied_paths →
  longest-prefix rule match → access mode gate.
- `PolicyEvaluation` returns `decision`, `matched_rule_id`, `workspace_id`.
- Legacy migration: normalize `allowed_paths` → one rule per prefix →
  set `default_access = none` → version 2 → atomic save.
- `StorageRecord::new()` defaults: `mcp_exposed = false`, policy v2
  no-access default.
- Workspace root may not be empty or `/`.
- Multiple workspaces on one storage are independent.
- Session cannot elevate policy.

## PR 03 — Native secret storage and plaintext migration

**Goal:** Move storage credentials and MCP bearer tokens out of JSON files
and prevent tokens from crossing the webview.

**Key contracts (see ADR 0003):**
- `SecretStore` trait with `put_json`, `get_json`, `delete`; status
  `Available` / `Locked` / `Unavailable`.
- `NativeSecretStore` (keyring), `MemorySecretStore` (tests),
  `UnavailableSecretStore` (error tests).
- Registry migration: backup first → extract secrets → write to keyring →
  remove from config → atomic replace → assert no plaintext remains.
- `SecretMutation` type for TypeScript/Rust interface: keep / set / clear.
- OAuth tokens never returned to TypeScript; single-use `PendingOAuthStore`.
- MCP auth token persisted as `auth_token_ref` only; `INFIMOUNT_AUTH_TOKEN`
  env var for headless use.
- Error sanitization removes raw `opendal::Error` details.
- Sensitive files created as `0600` (Unix), directories as `0700`.

## PR 04 — Shareable export, encrypted recovery, and safe import

**Goal:** Replace secret-inclusive raw exports and destructive blind imports.

**Key contracts (see ADR 0003 extensions):**
- `exportShareableConfig`: no secrets, no `secret_ref`, forces
  `mcpExposed = false`.
- `createRecoveryBackup`: passphrase-encrypted (age), armored, atomic,
  includes checksum.
- `previewStorageImport` / `applyStorageImport`: preview ID with 10-min
  TTL, revision-match check, transactional apply.
- Import default mode: merge; conflict handling: error.
- Raw JSON editor loads public config only; no keyring exposure.
- Rename to "Advanced public configuration".

## PR 05 — Version synchronization and bundled MCP sidecar

**Goal:** Make the normal desktop installation self-contained and ensure
desktop and MCP versions match.

**Key contracts (see ADR 0004):**
- Workspace `version = "0.8.0"` in root `Cargo.toml`.
- `SidecarLocator` discovers bundled binary; runs `--version` with 3s
  timeout; selects only same-version candidate.
- `prepare-mcp-sidecar.mjs`: build → copy → set executable → verify
  version → print SHA-256.
- Generated stdio config uses verified absolute path.
- No fallback to bare `infimount_mcp` on `PATH` for generated snippets.
- Release workflow builds sidecar first; post-bundle checks verify
  presence and version.

## PR 06 — Rust workspace service and browser-storage migration

**Goal:** Make Agent Workspaces durable, transactional, and first-class.

**Key contracts:**
- `WorkspaceRegistry` persisted at `~/.infimount/workspaces.json` with
  file lock, atomic writes, schema version, `0600` permissions.
- `create_agent_workspace`: validate storage → normalize root → reject
  overlap → stat → create files → write `.infimount/workspace.json` →
  add policy rule → persist → rollback on failure.
- Workspace deletion: default keeps files; destructive delete requires
  confirmation.
- Browser-localStorage migration: read → `import_legacy_workspaces` →
  validate → create records → remove localStorage entry only on success.

## PR 07 — Workspace-first activation wizard and client integrations

**Goal:** Replace informational onboarding with a verified
install-to-first-read workflow.

**Key contracts:**
- Six-step wizard: Safety baseline → Storage → Workspace → Sidecar →
  Client → End-to-end probe.
- Demo storage layout: `workspace/` (README.md, sample.txt) and
  `outside/` (denied.txt).
- `McpClientAdapter` trait: `detect`, `preview_install`, `apply_install`,
  `rollback`.
- Initial adapters: Generic stdio, Claude Code, Cursor, VS Code, OpenCode,
  Claude Desktop.
- MCP probe: spawn sidecar → initialize → `tools/list` → `list_dir` →
  `read_file` inside → `read_file` outside (expects denial).
- Probe timeouts: start 5s, initialize 5s, request 10s, total 30s.
- "Finish setup" enabled only after probe passes.
- Skip leaves a persistent incomplete-setup banner.

## PR 08 — Diagnostics and privacy-preserving product events

**Goal:** Make failures diagnosable without compromising local-first privacy.

**Key contracts:**
- Diagnostics may include: app/sidecar version, OS/arch, keyring status,
  config file states, schema versions, storage counts (no names),
  enabled tools, port availability, sanitized error codes.
- Diagnostics must not include: storage names, file paths, bucket names,
  endpoints, config JSON, credentials, tokens, file contents, prompts,
  presigned URLs.
- Product events: structured bounded set (app_launched, onboarding_*,
  storage_added, workspace_created, sidecar_verified, client_config_*,
  mcp_probe_*, activation_completed).
- Local JSONL event file (max 5000 events / 5 MiB, rotate oldest).
- Network export disabled by default (`TelemetryConsent::Unknown`).

## PR 09 — Operator cache, paginated listing, and streaming I/O

**Goal:** Prevent large remote directories and files from causing
excessive requests or memory usage.

**Key contracts:**
- `StorageRuntime` with `operator_cache` keyed by `storage_id + revision`.
- `ListEntriesPageRequest` / `ListEntriesPage`: cursor-based, non-recursive
  default 200, max 1000, max recursive 10,000.
- `read_file_range(storage_id, path, offset, max_bytes)`: default preview
  256 KiB, absolute max 2 MiB.
- Streaming transfers: 8 MiB buffer, progress per chunk, never `Vec<u8>`
  the whole file, cancellable.
- Benchmarks for 10K-object listing, 100K recursive, 1 GiB transfer.

## PR 10 — Tauri hardening, signing, and release publication

**Goal:** Make stable builds trustworthy and eliminate insecure stable-release
fallbacks.

**Key contracts:**
- `withGlobalTauri` = false unless proven necessary.
- Restrictive CSP: self, Tauri IPC, blob/data images only.
- Stable tag regex `^v[0-9]+\.[0-9]+\.[0-9]+$`.
- Stable macOS/Windows requires signing material; missing signing fails the
  workflow.
- Every release requires updater signing. Prerelease tags may omit platform
  app signing only with an `UNSIGNED` marker and prerelease status.
- Draft release → download → validate → publish automatically.
